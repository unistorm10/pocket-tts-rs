# Pocket TTS native Rust performance benchmark
**Run date:** October 26, 2026
**Environment:** self-hosted `elitedesk-mini`, Linux x86-64 via WSL2, Rust/XN CPU inference.
**Reference:** Kyutai `pocket-tts` v4.0.1 pinned at `a922b912dfa366975294afb568d815b305acde5d`.
**Inputs:** official revision-pinned, full encoder-enabled English, 7M, and 18M REFL checkpoints, authorized with `HF_TOKEN`. Kyutai's Alba audio as the reference-cloning input; pretrained Alba voice state for preset mode. Seed = 42.

**Status:** 288/288 genuine speech-generation trials passed, with 0 inference errors, across two independent benchmark modes:
- [144 trial fresh-process run](https://github.com/unistorm10/pocket-tts-rs/actions/runs/40377493188), [raw JSON/Markdown](https://github.com/unistorm10/pocket-tts-rs/actions/runs/40377493188/artifacts/12677901806)
- [144 trial warm resident-model HTTP run](https://github.com/unistorm10/pocket-tts-rs/actions/runs/40380071569), [raw JSON/Markdown](https://github.com/unistorm10/pocket-tts-rs/actions/runs/40380071569/artifacts/12677703174)

Each suite included three models × two voice paths × three text lengths × two CPU thread counts × two quantization modes × two repeats. Values below show medians of 6 observations combining lengths, and are not isolated to a fixed-length utterance. See the JSON artifacts for exact per-trial measurements.

## Voice-state caching is the crucial latency improvement

The HTTP server retains the model and an LRU of voice states. The first reference-audio request must encode the WAV and populate the cache; subsequent requests use the exact same cloned voice state without repeating the encoder.

| Model, 4-thread FP32 | First uncached clone TTFA | Cached clone TTFA median (5 requests) | Cached observed range |
| --- | ---: | ---: | ---: |
| Default English | 1,789 ms | 125 ms | 109–166 ms |
| English 18M REFL | 1,543 ms | 28 ms | 27–42 ms |
| English 7M | 1,414 ms | 20 ms | 18–34 ms |

One cold measurement per server configuration is **not** a statistically stable cold percentile. The mixed resident reference-audio p95 values are distorted upward by that single first-run cost. For rigorous p95, compare cold and cached cohorts independently with more repetitions.

**Takeaway:** On this runner, INT8 saves memory but is often **slower**, especially for the full English model. Use FP32 as the default speed baseline on this x86-64 CPU; consider INT8 for memory pressure and verify per target, rather than assuming integer quantization improves TTFA.

## RTF vs generated speech throughput

`RTF = processing wall time / generated audio duration`, lower is better. Inverse `1/RTF` is generated audio seconds per processing second. 7M's warm FP32 preset RTF 0.069 corresponds to ~14.5× real time; English's RTF 0.319 corresponds to ~3.1×. New-process measurements include cold model and reference preparation. Resident measurements retain the model. Both RTF denominators exclude the fixed 200 ms silence appended by Kyutai's WAV writer. The `model_only_rtf` field in the process artifact is derived from Kyutai's own per-chunk generation logs, which exclude model loading and reference encoding.

## TTFA measurement caveat

TTFA measures the arrival of the first streaming audio chunk containing a sample above 1% of full-scale PCM. Header arrival is recorded separately and not mistaken for audio. The benchmark also records a first-PCM timestamp and leading-silence-adjusted *estimated* audible onset. Real output-device scheduling, DAC latency and subjective listening are not measured. Different numbers for warm and new-process TTFA are expected and should never be combined in one ranking.

## Coverage and missing acceptance gates

**Measured:** all 3 supported full Kyutai English-family checkpoints, preset/reference conditioning, real 24kHz PCM, short/medium/long, CPU 1/4 threads, FP32/INT8, native stdout and HTTP streaming, model startup, first PCM, first audible chunk, end-to-end and model-only RTF, process RSS, timing variation, cold versus cached reference audio.

**Not measured yet:** in-process Candle runtime, real CUDA or ARM64/Rockchip devices, battery power/thermal throttling, simultaneous concurrent HTTP requests, ASR WER/CER, MOS/UTMOS, speaker embedding similarity and subjective quality. The official Rust HTTP server itself serializes generation behind a mutex. Those missing metrics **cannot** be inferred from RTF or signal amplitude.

Results are linked above. Reproduction instructions and raw definitions are in [BENCHMARKING.md](BENCHMARKING.md). The two expensive full-model benchmark Actions workflows are configured **manual-only** after these verified runs.

**Design conclusion:** provide long-lived model sessions and reuse voice-state embeddings, benchmark FP32 first for speed on this CPU and adapt the existing Candle neural code against this exact verified Rust/XN baseline instead of recoding FlowLM or Mimi from scratch.
